# dsh-tada

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的原生桌面通知，按普通 DSH 插件安装即可使用。

[English](README.md) | **简体中文**

当 Agent 完成一轮对话、出错、等待你批准或回答时，dsh-tada 会用打扰最小的方式提醒你：

| 你正在…… | 提醒方式 |
|---|---|
| 查看刚刚结束的会话 | 不提醒，内容已经在屏幕上 |
| 在 DSH 里查看其他会话 | 应用内提醒（toast） |
| 在其他应用里 | 系统通知 |

通知由 DeepSeek Harness 亲自发出，所以系统通知中心显示的是 DSH 的应用名和图标，点击通知即可打开对应会话。插件不修改 DSH 的任何代码，也没有运行时依赖，桌面端和 `dsh web` 都可以使用。

所有提醒都由插件观察到的 DSH 事件触发，不依赖模型自己决定何时提醒。

## 安装

```sh
dsh plugin --profile desktop add dsh-tada   # 桌面端
dsh plugin --profile web add dsh-tada       # dsh web
```

可以用版本号锁定，例如 `dsh-tada@0.2.0`。在网页界面中，也可以通过 **设置 → 插件 → 添加插件** 输入 `dsh-tada` 来安装。

### 从本地目录安装

```sh
dsh plugin --profile desktop add /path/to/dsh-tada
```

客户端构建产物已经提交到仓库，从本地目录安装不需要再执行安装或构建。

### 离线安装

目标机器无法访问 npm 时，先打包，再把 tarball 拷贝过去安装：

```sh
npm pack
dsh plugin --profile desktop add ./dsh-tada-0.2.0.tgz
```

## 配置

打开 **设置 → 通知**。点击 **保存** 后立即生效，无需刷新或重启。

- **通知内容**——编辑标题和正文模板，支持实时预览。
- **应用内提醒**——1–30 秒后自动消失，或一直显示，直到点击 **查看** 或 **关闭**。
- **通知行为**——总开关和各事件开关。
- **高级**——通知通道、应用名、通知语言、免打扰时段、最小提醒间隔、正文最大长度。

### 默认提醒的事件

| 事件 | 默认 |
|---|---|
| 轮次结束、出错、等待批准、等待回答 | 开启 |
| 子任务、工作流、目标完成 | 关闭 |

### 模板预设

标题和正文可以混排固定文字和以下预设：

| 预设 | 内容 |
|---|---|
| `{{app}}` | 应用名（默认 `DSH`） |
| `{{event}}` | 本地化的事件名，例如 `任务完成` |
| `{{session}}` | 会话标题 |
| `{{workspace}}` | 工作区名 |
| `{{detail}}` | 回复摘要、错误信息、问题内容或工具原因 |

默认标题为 `{{event}}`，默认正文为 `{{session}}`。无法识别的预设会原样显示，方便发现拼写错误。

### 免打扰与提醒频率

- 免打扰时段使用 `HH:MM-HH:MM` 格式，支持跨夜。它只静音自动的轮次结束提醒；审批、提问、子任务/工作流/目标提醒始终送达。
- 最小提醒间隔（默认 1500 毫秒）限制同一会话的轮次结束提醒频率。
- 通知正文默认跟随应用语言，也可以强制使用中文或英文。

## 常见问题

- **收不到系统通知？** 桌面端通常会自动授予通知权限；在浏览器（`dsh web`）中使用时，请在页面请求权限时允许通知。
- **升级后提醒异常？** 刷新 DSH 页面，让新的 Client 生效；Host 侧更新后需要重启 DSH。
- **需要排查问题？** 仅本机可访问的状态接口会返回通知通道状态，其中不包含任何密钥：

  ```sh
  curl -s "$DSH_WEB_URL/dsh-tada/status"
  ```

## 开发

```sh
npm install
npm test        # 先重新构建客户端，再运行测试
npm run check   # 构建 + 预检 + 测试
```

Host 部分在 `lib/` 中，是普通的 ESM 代码。Client 部分由 `src/client/` 构建为已提交的 `client/client.js`——请修改源码，不要直接改构建产物。
